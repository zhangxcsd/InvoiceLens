# 菜单命名约定（UI 高保真阶段）

## 目标

统一侧边栏、面包屑、页面标题的命名风格，降低理解成本，避免同级菜单出现“有的叫库、有的叫企业、有的叫管理”这类不一致。

## 命名后缀规范

- `库`：表示沉淀后的集合数据与查询入口  
  例：`全量企业数据库`
- `组织`：表示一个业务分组或域  
  例：`被审企业组织`
- `台账`：表示可维护的主数据清单（录入/导入/编辑）  
  例：`主数据台账`
- `关系树`：表示层级结构视图（可展开节点）  
  例：`管理关系树`、`产权关系树`
- `视图`：表示对照、解释、展示型页面（非直接维护）  
  例：`管产关系视图`
- `分析`：表示关联、计算、诊断型页面  
  例：`发票关联分析`

## 已落地命名（企业组织维度）

- `被审企业组织`
  - `管理与产权层级信息`
  - `管理关系树`
  - `产权关系树`
  - `管产关系视图`
- `发票报送覆盖分析`（企业组织维度下与「被审企业组织」同级入口，不再使用已废止分组名「票企关联视图」）
- `全量企业数据库`

## 使用规则

- 同一个功能在不同位置（侧边栏/面包屑/页面标题）应使用同名，不做同义词替换。
- 一级或二级分组优先用“组织/管理”，具体功能页按“台账/关系树/视图/分析”收口。
- 新增页面先确定“页面类型后缀”，再确定业务前缀，避免临时命名。

## 本阶段边界

- 本约定优先服务前端高保真原型与信息架构一致性。
- DDL、接口字段命名可后续再按数据建模规范单独制定，与菜单文案解耦。
